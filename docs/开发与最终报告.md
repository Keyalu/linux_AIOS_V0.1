## 1. 双通道意图识别

**核心函数**：`HostAgent.understand_intent()`（`group_1/host_agent.py`）、`_RULES`、`_extract_params()`。

**实现要点**：
- 规则路径优先：`_RULES` 是一组 `(正则, action, 描述)` 元组，按顺序匹配。"点击/单击/双击"排在"打开/启动"之前，保证"点击文件"不被"打开"抢走；命中即返回，零延迟零 token。
- LLM 路径兜底：规则未命中时，SYSTEM_PROMPT 注入动作清单、JSON 输出契约、示例与边界（如"open_url 只能打开网址"），要求输出 `{intent, goals:[{action,target,params}]}`。
- 参数抽取按 action 分派：open_app 取"打开/启动"后的实体；click_element 优先引号内容，否则剥掉"请/帮我/点击/label/按钮"等前后缀，再把"图标/按钮/菜单项"映射为 AT-SPI role 名。
- 输出 `intent_json` 契约：`intent_id`（uuid）、`user_text`、`timestamp`、`language=zh-CN`。

**bug 修复**：
- **"点击 label，文件"被误判为地址栏导航**：原动作集无 click 类动作，LLM 把它判为 navigate（confidence 0.4），规划层又硬编码 `Ctrl+L→type→Enter` 地址栏序列，于是在文件管理器地址栏里输入"label"。修复：意图层新增 `click_element` 动作（规则触发词 + LLM prompt 示例 + 参数抽取）。

## 2. 意图后处理归一

**核心函数**：`understand_intent()` 尾部归一段、`_resolve_target()`。

**实现要点**：不信任 LLM 原样输出，执行语义字段全部在组1 后处理层强制归一：
- `send_email.dry_run`：正则"草稿|预览|别真发"判定，出现发件动作即真发（安全交给提权流）；
- `attachment`：正则从用户原话抽取文件路径，覆盖 LLM 的 null；
- 多个 send_email goal 自动合并为一条、附件收进列表；
- `_resolve_target`：把"demo_task"这类口语称呼解析为真实目录——相对路径依次在默认工作目录、cwd、`~` 下查找，绝对路径不存在则回退默认目录。

**bug 修复**：本节为既有设计，本次无新增修复；但其归一思想是后续所有改动的范式（执行语义字段不由 LLM 决定）。

## 3. 任务规划与参数填充

**核心函数**：`TaskPlanner.plan()`、`_steps_for()`、`_fill_params()`（`group_2/task_planner.py`）。

**实现要点**：
- goals 按动作分三类：`_TOOL_ACTIONS`（工具→组4 技能映射）、`_GUI_ACTIONS`（GUI→步骤序列）、其余 unresolved。
- `_fill_params` 三层填参：① `intent.params` 直接采用（带类型防御：LLM 偶尔把结果对象塞进字符串参数，dict/list 一律丢弃）；② 缺口处用 schema 第一个字符串参数接目标；③ 数值参数留空由技能默认兜底。required 缺参记 unresolved。
- 输出 `plan_json`：`steps[{step_id,kind,action,target,params,requires_admin,description}] + elements{} + unresolved[]`。

**bug 修复**：
- **NameError: last_file_target**：`plan()` 把该参数传给 `_steps_for`，但后者调 `_fill_params` 时没透传，函数体却引用了它。LLM 路径因显式给了 src 短路未暴露，规则路径 src 为空必崩。修复：补形参并在调用处透传。

## 4. AT-SPI 控件树探测

**核心函数**：`ControlDetector.detect_elements()`、`find_element()`、`refresh()`（`group_2/control_detector.py`）。

**实现要点**：
- 三后端降级：pyatspi → atspi-gi（GNOME 预装，无需 pip）→ mock（硬编码近似快照）。
- 从 desktop 根遍历各应用进程，每应用 DFS 下钻；每个可见对象输出契约 `{app, role, name, bbox:[x,y,w,h], depth}`，bbox 取 SCREEN 屏幕坐标。
- `find_element(role,name,retries,interval)`：role 精确、name 匹配；`refresh()` 清空 desktop 缓存供窗口切换后重查。

**bug 修复**：
- **预算不足，dock 图标物理上采不到（核心 Bug）**：原默认预算 `max_depth=6 / max_nodes=500 / max_children=40`，而 Ubuntu 实测 dock 上"文件"位于 depth=12——永远采不到。type/hotkey 不需要遍历树所以一直正常，click 必须查树拿 bbox 才暴露。修复：预算对齐到 `8000/24/80`（与组3 AtspiIO 同量级）。
- **遍历失败静默伪造假元素**：except 分支原返回硬编码英文假元素（Files/Firefox/Text Editor），系统以为查到了、实则在假数据里找中文名。修复：真实后端失败诚实返回空；仅 mock 后端保留模拟元素。
- **名称匹配方向写反**：原 `name not in el["name"]` 要求查询名是元素名子串；用户说"文件管理器"树里叫"文件"，方向反了。修复：双向子串 `(name in el["name"]) or (el["name"] in name)`。
- **动态 UI 渲染竞态**：Super 后搜索结果异步渲染，立即查树查不到。修复：`find_element` 增 `retries/interval`，执行端 element_query 自动 `retries=3, interval=0.5`。

## 5. GUI 动作执行

**核心函数**：`Automator.click/type_text/hotkey()`、`AtspiIO.click_at/hotkey/set_text`（`group_3/automator.py`、`atspi_io.py`）。

**实现要点**：每个动作四级降级——
- **click**：AT-SPI `do_action(0)` 控件级触发 → bbox 取中心点 `click_at(x,y)` 合成鼠标事件 → pyautogui 坐标点击 → Mock；
- **type_text**：`find_accessible(role="text")` 找焦点输入框 → `set_text_contents`（中文最可靠）→ 否则逐字符 keysym 合成；
- **hotkey**：修饰键按下 → 末键 pressrelease → 修饰键逆序释放，组合键状态干净。
- 每个步骤附 before/after 状态快照。

**bug 修复**：
- **AT-SPI 可用性判定把函数当布尔**：`available as _atspi_ok` 后直接 `if _atspi_ok`，函数对象恒真，无 AT-SPI 环境必崩。修复：改为 `_atspi_ok()` 调用。
- **AT-SPI 哨兵坐标误点**：不可见菜单项 bbox 为 `[-2147483648,-2147483648,1,1]`，原逻辑有 bbox 就取中心合成点击。修复：坐标分支要求 `x>=0,y>=0,w>0,h>0`。
- **截图过快拿到过渡帧**：`take_screenshot` 入口固定 `time.sleep(2)`。

## 6. open_app 应用启动

**核心函数**：`TaskPlanner._gui_open_app_steps()`（`group_2/task_planner.py`）。

**实现要点**：双路径——规划时先 `find_element(name=app)`：
- **命中**（dock/桌面已有图标）→ 单步 click 直点，不按 Super；
- **未命中** → `hotkey super → type app → click(element_query)` 走活动概览搜索路径，执行端自动轮询等结果渲染。

**bug 修复**：
- **查到图标仍绕 Super**：原实现无论命中与否都生成"Super→type→click"三步，命中时 click 用的还是按 Super 前 dock 旧坐标。修复：命中即短路为单步 click，未命中才走通用启动路径。

## 7. click_element 控件直点

**核心函数**：`_extract_params("click_element")`、`TaskPlanner._gui_generic_steps` 的 click_element 分支。

**实现要点**：意图层识别"点击 X"→ 规划层 `find_element(role,name)` 预定位：命中则 click 步骤内嵌 element（带 bbox，执行时零查找直接点）；未命中带 `element_query`，执行端 `app_agent._detector_find` 现场重查（自动轮询）。

**bug 修复**：与第 1、4、5 节同源——新增动作时暴露了导航误判、控件树采不到、执行定位弱三个问题，一并修复。

## 9. 安全沙箱与两阶段确认流

**核心函数**：`SystemCoordinator.plan_only()` / `execute_approved()`（`group_5/coordinator.py`）。

**实现要点**：
- `plan_only()` 完成"意图→安全检查→规划→控件探测"，**不执行**；`needs_confirm = requires_admin 步骤 ∪ 非 dry_run 的 send_email`。
- 确认后 `execute_approved()` 原样执行已批准 plan，**执行阶段零 LLM 二次规划**——PENDING token 存完整 `{intent,plan,check}`，杜绝"确认方案≠执行方案"。
- 安全未通过直接拒绝并落盘；无安全模块时 `SecuritySandboxStub` 兜底。

**bug 修复**：本节为既有稳定设计，本次无新增修复。

## 10. 提权流与自愈流

**核心函数**：`AppAgent._call_contract()`、`_resolve_refs()`（`group_3/app_agent.py`）。

**实现要点**：工具失败按错误前缀分流——
- "权限不足"开头 → `confirmer` 征询用户 → 同意后以 ADMIN 重试一次；
- "工具未注册"开头 → `difflib.get_close_matches(cutoff=0.6)` 模糊匹配工具名 → 纠错重试；
- `{{prev_result}}`/`{{stepN.result}}` 占位回填上一步输出；
- 常驻单例的 `escalated`/`self_healed` 每次 execute 开头清空，防跨会话泄漏。

**bug 修复**：本节为既有稳定设计，本次无新增修复。

## 11. 审计与 RAG

**核心函数**：`SystemCoordinator._persist()`、`audit()`、`_consistent()`。

**实现要点**：每次运行写五件套 JSON（intent/check/plan/session_log/audit）；审计 JSONL 逐条追加带时间戳；`_consistent()` 对账组3 自报计数与逐条步骤，不一致则 verdict 判 FAIL；RAG `add_trace` 记录动作序列，`query(user_text,3)` 召回历史轨迹。

**bug 修复**：本节为既有稳定设计，本次无新增修复。

## 验证与结论

- 集成测试 13 项中 12 项通过；唯一失败 test_s6 为既有 LLM 非确定性（规则路径完整通过）。
- 规则与真实 LLM（glm-5.3-flash）双通道下，"点击label，文件"均正确输出 `click_element {name:文件, role:label}`。
- Ubuntu 24 实测：atspi-gi 加载成功，dock"文件"在 depth=12 被采集（`bbox=[0,102,66,60]`），click 走合成坐标点击，不再落 Mock。
- 零新依赖；`system_out/`（LLM Key、SMTP 授权码）整目录 gitignore，推送零泄漏。

本次迭代修复的 10 个 bug 全部指向同一工程原则：**失败必须可见**——探测失败不再伪造元素、哨兵坐标不误点、执行语义不由 LLM 随机决定。后续方向：dock/概览定向子树遍历、LLM 工具参数固化、Wayland 下 DoAction 覆盖度实测。
